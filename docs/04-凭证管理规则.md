# 🔑 凭证管理规则（第 4 号文件）

> 本规则由笔者于 2026-10-14 亲自授权设立，是对 [[【第0号】知识库宪法]] 的**专项补充**。
> 与宪法冲突时，以宪法为准；宪法未覆盖的凭证事项，以本规则为准。

---

## 一、授权原话（2026-10-14）

> 「其实这台电脑的账号密码是可以保存到本地知识库的，因为我上传的账号密码都是共用的。」

**结论**：**共用/通用账号密码**不再是脱敏对象，可以明文写入本地知识库。

---

## 二、唯一合法落点

所有共用凭证**只能**写在一处：

> `03_领域/工具与技术/名单-共用账号密码.md`

规则：
1. 一份文件集中管理，**不分散写**在别的笔记里（避免改了一处忘另一处）。
2. 单条记录格式：`系统 | 网址 | 账号 | 密码 | 备注`。
3. 新增/修改凭证后，同步刷 `updated` 字段 + 在 [[知识库变更日志]] 追加一行。
4. 文件必须保持双链连接（挂在 MOC 上），不能成孤岛。

---

## 三、可以写 / 绝对不写

| 类别 | 能否入本地库 | 说明 |
|---|---|---|
| 共用/通用系统账号（公司共用、多人使用） | ✅ **明文可写** | 如统计分析软件站点、公司共用平台 |
| 共用账号的密码 | ✅ **明文可写** | 同上，笔者明确授权 |
| 个人专属密码 | ❌ 永不 | 只属于你一个人的系统 |
| 邮箱密码（含各类个人/企业邮箱） | ❌ 永不 | — |
| 金融/支付/银行/UKey 凭证 | ❌ 永不 | — |
| **笔者本人**的证件号、身份证、护照 | ❌ 永不 | 个人身份凭证，无条件排除 |
| **他人的证件号（员工身份证号）** | ⚠️ **有条件可写** | 见下方「三·附」：仅限业务填报反复取数，且须笔者逐次明确授权 |
| VPN 密钥、SSH 私钥、API Secret | ❌ 永不 | — |
| 需要二步验证的临时码 | ❌ 永不 | 时效性太短，写即过期 |

**拿不准的一律先问笔者**，不要自己判断。

### 三·附 · 他人证件号的有条件授权（2026-10-20 设立）

**背景**：资质认定 / 项目评价等填报每年要反复取员工身份证号；曾因源表把号码存成数字导致 18 位截断、决定不入库，**源文件已修复**。
笔者明确指示：员工身份证号与联系电话全量录入知识库。

| 约束 | 内容 |
|---|---|
| 适用对象 | **仅限他人**（员工）。笔者本人的证件号仍属「永不」 |
| 唯一落点 | `03_领域/业务数据/名单-研发人员-<年度>.md`（不分散写进其它笔记） |
| 前置校验 | 号码须经 **18 位格式校验 ＋ 与出生年月交叉校验**，全通过才入库 |
| 标记要求 | frontmatter 必带 `security: 🔴 含身份证号 + 联系电话 · 严禁外传/上传云端` ＋ tag `敏感数据` |
| 外传红线 | 完全适用 §五（不上传云端/网盘、不进对外文档与分享链接） |
| 出口 | 笔者随时可撤销；撤销时须**清除字段并回退本条登记** |

## 四、使用规范（AI 侧）

1. **读取**：需要登录凭证时，先查 `名单-共用账号密码.md`，查不到再问笔者；不要让他重复粘贴。
2. **写入**：笔者给出新的共用账号密码时，主动登记进名单（属低风险新建内容，L2 可做，事后报备）。
3. **日志脱敏例外**：本地工作区日志可记录凭证线索；但**发布/分享类产出**（报告、看板、对外文档）里**绝不带**账号密码。
4. **验证后回写**：如果密码失效（如登录报错），先在名单里标注「疑似失效·YYYY-MM-DD」，找笔者确认后再改。

---

## 五、外传红线（比脱敏更重要）

1. **不同步云端 / 资料库**：含凭证的笔记**禁止**上传任何云端备份渠道。备份前必须跳过凭证文件。
2. **不发给第三方**：不在任何对外消息、邮件、共享链接里贴凭证。
3. **不随库迁移**：将来若整理/迁移/导出知识库，凭证文件必须最后人工处理。
4. 本机铁律仍然优先：文件不写系统盘、不写桌面。
