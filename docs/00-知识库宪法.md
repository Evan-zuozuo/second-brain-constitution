# 📜 知识库宪法（第 0 号文件 · 最高效力）

> 本文件是这个知识库的**根本大法**。任何其它规则与它冲突时，以本文件为准。
> 修改本文件必须由笔者明确同意，AI 不得擅自更改。

---

## 一、这个知识库是干什么的

**一句话定位**：把笔者工作中遇到的「知识 / 问题 / 解决方法」沉淀成**可复用、可检索、可回溯**的资产。

**三个核心用途**：
1. **复用** —— 再遇到同类问题，能直接查到当初怎么解决的。
2. **连接** —— 知识点之间用双链连起来，看到 A 能想起 B。
3. **沉淀** —— 灵感、零散笔记经过分析后变成结构化的知识。

**明确不做什么**（避免边界膨胀）：
- 不做日记式流水账（日记只记「事实 + 当天收获」，不记情绪宣泄）。
- 不做素材仓库（不收藏整篇文章，只提取「对我有用的那一句 + 我的理解」）。
- 不做第二大脑的「垃圾场」（进不来的知识宁可不记，规则见第五节）。

### ✅ 业务数据入库分级规则（重要）

> **前提事实**：业务数据本已存在于日常对话、公司共享盘、本地工作区 —— **写进本库不新增暴露面**。
> **∴「保密」不是拒绝入库的理由**。真正的风险是**「库被台账化」**（违反本节「不做素材仓库」）：
> 数字每天变 → 入库即成化石；台账体积大 → 淹没方法笔记；明细无法双链 → 变孤岛。

**按「数据性质」四级**（判据＝进库后**还有没有复用价值**，而非密级）：

| 级 | 判据 | 处理 | 落位 |
|---|---|---|---|
| **A 直接入** | 稳定（不随时间变）＋ 可复用 | 正常入库 | `03_领域/业务数据/` 或对应领域、知识库 |
| **B 整理后入** | 有价值但含敏感值 / 会变 | 入**结构、口径**，不入当期值；标 `snapshot_date` | 同上 |
| **C 只入指针** | 会变 ＋ 体积大 ＋ 明细无复用价值 | **不复制内容**，只写「是什么 / 在哪 / 口径 / 怎么更新」索引笔记 | 同上 |
| **D 不入** | 无复用价值 | 私人数据｜个人专属凭证｜私有配置（`folder_id`·任务 UUID·本机路径）｜过程产物 | 原地 |

**配套三条**：
1. 业务数据笔记统一打 tag `#业务数据/<域>`；
2. frontmatter 增 `snapshot_date:`（数据快照日期），过期一眼可见；
3. **AI 检索、问答默认不扫业务数据区**，显式点名才读。

> 🔴 仍**绝对不入**：**私人数据**（手机号／证件号／本名／健康／财务凭证 → 归口敏感区）、
> **个人专属凭证**、**云端/服务器凭证**（非怕人看，是怕被程序或日志带出去）。

## 二、文件夹框架（PARA + 卡片盒 混合）

数字前缀只为了**排序和一眼定位**，不代表重要性。

| 目录         | 定位                        | 类比     | 生命周期         |
| ---------- | ------------------------- | ------ | ------------ |
| `00_系统`    | 规则、模板、看板、附件存放             | 发动机舱   | 极少动          |
| `01_收件箱`   | **一切新东西的落点**，未分类的临时区      | 门厅     | 必须定期清空       |
| `02_灵感文件`  | 笔者丢进来的灵感和外部笔记，**等 AI 分析** | 待加工的矿石 | 分析后移入 `_已沉淀` |
| `03_领域`    | 长期关注的主题领域（不结项）            | 图书馆分区  | 长期生长         |
| `03_领域/业务数据` | **公司业务参考数据隔离区**（按 A/B/C 分级入；AI 默认不扫） | 档案柜 | 随业务更新 |
| `04_项目`    | 有明确目标和终点的任务               | 施工现场   | 结项后归档        |
| `05_知识库`   | **核心资产**：概念/排查/经验/SOP     | 金库     | 永久           |
| `06_索引MOC` | 主题地图，把散落笔记串起来             | 书架标签   | 长期维护         |
| `07_日记`    | 每日工作记录                    | 船日志    | 按年归档         |
| `08_归档`    | 已完结、暂时不用的东西               | 仓库     | 只进不出         |

### 关键区分：`03_领域` vs `05_知识库`

- **领域** = 「我关注什么」→ 按主题分文件夹，是**内容的长驻位置**。
- **知识库** = 「我学到了什么」→ 按**知识形态**分文件夹（概念/排查/经验/SOP）。

**实操简化约定**（避免两头放）：
> - 一条笔记如果**属于某个领域**，就放到 `03_领域/<领域>/` 下。
> - 如果它是一条**独立成型的知识点**（尤其问题排查、SOP），放到 `05_知识库/` 对应子目录。
> - **同一内容只放一处**，另一处用双链引用，绝不复制两份。

## 三、双链规则（这是「改一处、全部跟着改」的关键）

Obsidian 的机制决定了：**只要用 ``文件名`` 引用，改文件名时全库引用会自动更新**。所以规则必须围绕「文件名」设计。

### 3.1 命名规则（唯一、稳定、可搜索）

| 笔记类型 | 命名格式 | 示例 |
|---|---|---|
| 概念笔记 | `概念-XXX` | `概念-挣值管理EVM` |
| 问题排查 | `排查-XXX问题` | `排查-Outlook无法接收附件` |
| 经验教训 | `经验-XXX` | `经验-跨部门沟通要先对齐目标` |
| 流程SOP | `SOP-XXX流程` | `SOP-客诉8D报告流程` |
| 项目笔记 | `项目-XXX` | `项目-规格书抽取工具` |
| 名单/花名册 | `名单-XXX` | `名单-某项目在职人员-2601` |
| 灵感/素材 | `YYYYMMDD-简短描述` | `20261008-Obsidian双链技巧` |
| MOC 索引 | `MOC-XXX` | `MOC-项目管理` |
| 日记 | `YYYY-MM-DD` | `2026-10-08` |

**硬性要求**：
1. **全库文件名唯一**（前缀已经保证了大类不重名，同类里也不许重名）。
2. **文件名即标题**，不在文件里再写一遍大标题占位（用 frontmatter 的 `title` 即可，正文可用 `# 标题`但要和文件名一致）。
3. **禁止**在文件名里出现 `/\:*?"<>|` 这些非法字符。
4. 改名字要通过 Obsidian 的重命名功能（或让 AI 改），**不要在外层文件管理器里直接改**，否则链接可能断。

### 3.2 引用规则

- 正文里提到另一个知识点，**必须用 `` 双链**，不要只写文字。
- 引用时**优先用 `文件名|显示文本`** 让句子通顺，例：`详见 排查-Java服务内存溢出|内存溢出排查记录`。
- **不要**用 `!` 嵌入大段内容（会失去链接追踪意义），只在需要展示时才嵌入图片。
- 每条笔记**至少要有 1 个出链或入链**，孤岛笔记要被 `MOC` 收编（见 3.4）。

### 3.3 反向链接（Backlink）约定

- 每篇笔记底部可以有 `## 🔗 相关` 段落，手动维护「我认为相关」的链接。
- Obsidian 原生反链面板会自动显示「谁引用了我」，这个不用手写。
- **AI 在沉淀时**：必须在新建笔记里补 `## 🔗 相关`，否则视为未完成沉淀。

### 3.4 MOC（Map of Content，内容地图）

- 每个大的领域/主题，在 `06_索引MOC/` 建一个 `MOC-XXX.md`。
- MOC 是**纯链接清单 + 一句话说明**，不写长内容。
- 新建任何笔记后，**必须挂到至少一个 MOC 下**（这是防止孤岛的兜底）。
- 用 Dataview 可以做**自动 MOC**（见模板），但人工 MOC 优先。

## 四、Frontmatter 元数据规范（所有笔记统一）

每篇笔记开头必须有（Templater 会自动填）：

```yaml
---
title: 笔记标题（与文件名一致）
type: 概念 | 排查 | 经验 | SOP | 项目 | 灵感 | MOC | 日记 | 参考 | 索引卡 | 模板 | 提案 | log | 体检报告 | 规则
domain: 工作方法 | 工具与技术 | 业务与行业 | 软技能与沟通 | 业务数据 | 其他
status: 草稿 | 已沉淀 | 已归档 | 已取代
created: YYYY-MM-DD
updated: YYYY-MM-DD
source: 来源（人/书/网/自己经历）
tags: [领域/子领域, 主题]
---
```

**`type` 决定它属于哪个文件夹**：由 `type` 反查第二节的表即可知道该放哪。

## 五、边界规则（AI 能做什么、不能做什么）

> 笔者原话：**「防止以后大返工」** —— 边界清楚才不会返工。

### ✅ AI 可以自主做（无需询问）
1. 读**任何**笔记（只读）。
2. 在 `01_收件箱`、`06_索引MOC`、`07_日记` 里**新建**文件。
3. 在 `05_知识库` 里**新建**沉淀笔记（但必须走第六节的沉淀流程）。
4. 更新 `updated` 字段、补 `## 🔗 相关` 链接。
5. 把 `02_灵感文件` 里处理完的条目移到 `02_灵感文件/_已沉淀`。

### ⚠️ AI 必须先问才能做
1. **修改或删除** `03_领域`、`05_知识库` 里**已有的**正文内容（改错别字可以例外，但要在回复里说明）。
2. **重命名**任何已有笔记。
3. **移动**已有笔记到别处。
4. **合并/拆分**笔记。
5. 修改本宪法或 `00_系统/01_规则与公约` 下的任何规则。

### ❌ AI 绝对不做
1. 删除任何文件（只移动到 `08_归档`，永不真删）。
2. 覆盖笔者手写的内容而不留痕迹（要改就改成「追加 + 标注」的形式）。
3. 在 `02_灵感文件` 里删除笔者丢进来的原始素材（只移不删）。
4. 往库里写入任何**未经确认的对外发布内容**。
5. 把知识库内容同步到外部（除非笔者明确要求）。

## 六、灵感沉淀流水线（标准流程）

```
丢素材 → 02_灵感文件/
      ↓
AI 分析（提炼：这是什么？对我有什么用？和已有知识什么关系？）
      ↓
产出提案（在 01_收件箱 生成「沉淀提案」笔记）
      ↓
笔者确认（或 AI 按规则自动落库，见第八节自动化等级）
      ↓
写入 05_知识库 或 03_领域（做成原子笔记，带双链）
      ↓
挂到对应 MOC
      ↓
原素材移到 02_灵感文件/_已沉淀/，并在素材里加一行「已沉淀 → `新笔记`」
```

**沉淀时的质量红线**：
- 一条笔记**只讲一件事**（原子化）。如果素材里有 3 个知识点，就拆成 3 条笔记。
- **一次摄入动 ≥ 3 页**（新建 + 更新 + 改 MOC 合计），只动 1 页视为「摘要式假动作」，重做。
- 必须有「**我的理解 / 对我的用处**」段落，不能只是原文搬运。
- 必须写 `## 🔗 相关` 关联至少一条已有笔记。

## 八、自动化等级（AI 处理时参照）

| 等级 | 含义 | 适用 |
|---|---|---|
| **L0 只读** | 只分析，不改 | 笔者明确说「只是看看」 |
| **L1 建议** | 生成提案，等确认 | 默认等级，尤其涉及已有笔记 |
| **L2 自动落库** | 直接写入新笔记，事后报告 | `05_知识库` 新建、灵感沉淀（低风险） |
| **L3 自动改** | 自动修改已有内容 | **永不自动**，必须逐次确认 |

**默认等级 = L1**。笔者说「你直接沉淀吧」→ 升到 L2。涉及修改已有笔记 → 无论何时都是 L3。

## 附录：跨机器迁移附记（方法论）

> 本节为迁移附记，不改变上文各条款效力；冲突时以上文条款＋本节执行口径为准。
> 下表为通用化表述：`<VAULT_ROOT>` = 知识库根目录，`<WORKSPACE>` = 库外工作区，`<USER_HOME>` = 用户目录。

| 项 | 原机器 | 新机器 |
|---|---|---|
| 库根 | `<VAULT_ROOT_A>` | `<VAULT_ROOT_B>` |
| 工作区 | `<WORKSPACE_A>` | `<WORKSPACE_B>` |
| 用户目录 | `<USER_HOME_A>` | `<USER_HOME_B>` |
| 环境 | 域账号 + DLP + 组策略 + 受限权限 | 非域 + 无 DLP + 完整权限 |
| 编码 | md 无 BOM（本宪法 §三 既定） | 同左；**.ps1 保留 BOM**（PowerShell 5.1 中文刚需） |

**执行口径**：
1. 日记 / 元数据 / 报告 / 归档区内的原机路径为**历史实录，不回改**；操作性区域（00_系统～06_索引MOC）的路径已按上表改写。
2. 内网共享盘地址在新机器不可达，原文保留并视为「原机器环境笔记」。
3. 敏感文件（凭证、含证件号人员名单）已移入独立敏感区，**永不镜像**。
4. 存量数据正按本宪法并入；归档候选一律先入「待删除暂存区」，由笔者最终处置。
5. 「本机」在未标注时期的旧笔记中一律指**原机器**；新笔记「本机」指新机器。
