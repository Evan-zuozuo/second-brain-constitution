# 🤖 AI 协作规则（第 3 号文件）

> 这份是**给 AI 助手看的操作手册**。每次 AI 在本库工作前务必先读这份 + [[【第0号】知识库宪法]]。

---

## 一、AI 进场必读顺序

1. [[【第0号】知识库宪法]] —— 边界在哪
2. [[【第1号】分类落位速查表]] —— 东西放哪
3. [[【第2号】归档与维护规则]] —— 怎么维护
4. 本文件 —— 具体怎么干

---

## 二、标准任务一：沉淀一条灵感

**触发**：笔者说「分析一下灵感文件」「沉淀这条笔记」

**步骤**：
1. 读 `02_灵感文件/` 下的素材（**只读，不动**）。
2. 提炼：
   - 素材讲了几件事？（拆成 N 条原子笔记）
   - 每件事：是什么 / 对我有什么用 / 和哪条已有笔记相关。
3. **扫描已有知识库**，找出可以双链的已有笔记（用 Grep 搜关键词）。
4. 按模板生成沉淀笔记，写入 `05_知识库/` 对应目录。
5. 每条新笔记：
   - 补 `source:` 指向原素材
   - 补 `## 🔗 相关` 段落（至少 1 条）
   - 挂到对应 `MOC`
6. 把原素材移到 `02_灵感文件/_已沉淀/`，在素材末尾追加：
   ```
   > ✅ 已于 YYYY-MM-DD 沉淀 → `新笔记1`、`新笔记2`
   ```
7. **向笔者汇报**：沉淀了几条、分别是什么、放哪了。

---

## 三、标准任务二：对话沉淀

**触发**：笔者说「把这次沉淀一下」「这个问题记下来」

**步骤**：
1. 回顾本次对话的核心问题与解法。
2. 判断形态（概念/排查/经验/SOP）。
3. 走标准任务一的 3–7 步。
4. 如果本次对话**没产生新知识**（只是闲聊/查询），**要明说「本次无需沉淀」**，不要硬凑。

---

## 四、标准任务三：给已解决问题的沉淀（自动）

**规则**：每次对话结束时，如果**解决了实质问题**，AI **主动**沉淀到知识库（L2 等级），并在回复末尾一句话报备。

**不沉淀的情况**：
- 纯查询（查了个天气、搜了条新闻）
- 纯闲聊
- 内容已有同名笔记（改为**更新已有笔记**，且属 L3，需先问）

---

## 五、写文件的技术约定

| 约定 | 说明 |
|---|---|
| 编码 | UTF-8（无 BOM） |
| 换行 | LF 或 CRLF 均可，保持一致 |
| 路径 | 一律用绝对路径，禁止写系统盘和桌面（全局铁律） |
| 文件名 | 不含 `/\:*?"<>|`，不含开头结尾空格 |
| frontmatter | 必须带，字段见宪法第四节 |
| 双链 | 用 ``文件名``，跨目录也要能定位到（文件名唯一是前提） |

---

## 六、汇报格式约定

AI 每次沉淀后，用**这种格式**汇报（简短，不啰嗦）：

```
✅ 已沉淀 N 条：
1. `笔记名` → 05_知识库/问题排查/
2. ...
📌 原素材已移入 _已沉淀
⚠️ 待你确认：XXX（如果有）
```

---

## 七、红线（再强调）

- ❌ 不删任何文件
- ❌ 不改已有正文（L3，要问）
- ❌ 不重命名已有笔记（L3，要问）
- ❌ 不新建顶层文件夹（要问）
- ❌ **回答不带 [[]] 引用**（查询时必须带 `文件名` 引用，答不上来就明说「我没读到」）
- ❌ **摄入只动 1 页**（一次摄入动 < 3 页视为「摘要式假动作」，重做）
- ✅ 只读一切、新建低风险笔记、补链接、加元数据

## 八、新建/沉淀笔记硬校验清单（预防层）

> **AI 写完任何新笔记 / 沉淀笔记，交付前必跑这 8 项校验。任何 1 项不通过 → 不交付，先修。**

| # | 校验 | 不通过时怎么修 |
|---|---|---|
| 1 | frontmatter **8 字段全**（title / type / domain / status / created / updated / source / tags）| 缺哪个补哪个（参考现有同类笔记）|
| 2 | `type` 值在【第0号】§四枚举内 | 改 type 值，或**提案**扩枚举（不要自造）|
| 3 | `domain` 值在【第0号】§四枚举内 | 改 domain 值，或**提案**扩枚举 |
| 4 | 文件名带合法前缀（按【第1号】命名速查）| 重命名（必经 Obsidian 重命名以保双链）|
| 5 | 至少有 1 个 `[[]]` 出链 **或** 被某 MOC 反向链 | 加相关链接；或建/挂到一个 MOC |
| 6 | 挂到至少 1 个 MOC（业务笔记强制）| 加 `MOC-XXX` 出链 或 请 MOC 反向链到 |
| 7 | `status` 值在枚举（草稿/已沉淀/已归档/已取代）| 改 status |
| 8 | `tags` ≥ 1 项 | 补 tags（至少 1 项）|

**交付回报格式**（沉淀/新建笔记后必含）：

```
✅ 已沉淀 N 条：
1. 笔记名 → 05_知识库/...
📌 已通过硬校验 8/8
```

或：

```
✅ 已沉淀 N 条：
1. 笔记名 → 05_知识库/...
📌 已通过硬校验 6/8（待补：① source ② tags）
```

**诚实条款**：8 项里**任何 1 项标为"待补"后再交付，AI 需明说**，让笔者知道哪些维度未达标，不让缺漏被悄悄藏起。
